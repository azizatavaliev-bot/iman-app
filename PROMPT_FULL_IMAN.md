## 1. АРХИТЕКТУРА ПРОЕКТА (изучи, прежде чем писать код)

**Что это:** IMAN — Telegram Mini App для мусульман: трекер намазов, Коран (аудио, тафсир, заметки), заучивание (хифз со spaced-repetition), геймификация «савабом», квесты, истории.

**Стек:**
- Фронт: **React 19 + TypeScript + Vite + Tailwind v4 + react-router-dom v7**, PWA (`vite-plugin-pwa`).
- Бэк: **чистый Node** через `http.createServer` в `server.js` (Express НЕ используется) + **PostgreSQL** (`pg`).
- Авторизация и идентификация: **Telegram** (`initData`, `BOT_TOKEN`, вебхук). Вне Telegram (обычный браузер) пользователь анонимный — данные только в `localStorage`, синка нет.
- Синхронизация: `GET/POST /api/user/:telegramId` ↔ таблица `users(telegram_id BIGINT PRIMARY KEY, data JSONB, updated_at BIGINT)`.
- Аналитика: `POST /api/analytics` ↔ таблица `analytics`.
- Установлен, но НЕ используется: `@anthropic-ai/sdk` (можно задействовать в фиче 4).

**Структура репозитория (ключевое):**
- `src/App.tsx` — все роуты (`<Routes>`), тема, провайдеры.
- `src/pages/*.tsx` — экраны. `src/data/*.ts` — контент-массивы. `src/lib/*.ts` — утилиты/клиент API.
- `src/lib/api.ts` — вызовы внешних API (времена намаза, Коран, хадисы, реситоры) и утилиты (haptics).
- `src/lib/storage.ts` — локальное хранилище прогресса. `src/lib/sync.ts` — синк с сервером. `src/lib/analytics.ts` — события.
- `src/lib/adminConfig.ts` — `isAdmin(telegramId, username)` по списку `ADMIN_TELEGRAM_IDS`. ⚠️ Проверка ТОЛЬКО на клиенте.
- `server.js` — ручной роутинг: `if (req.url === "/api/..." && req.method === "GET") {...}`. Крипто через `createHmac`. Есть эндпоинты: `/api/user/:id`, `/api/admin/users`, `/api/admin/analytics`, `/api/analytics`, `/api/leaderboard`, `/api/dua-wall`, `/health`.
- `schema.sql` — схема Postgres (`users`, `analytics`).
- Контент базы знаний: `src/data/tafsir-saadi.json` (~11 МБ, тафсир Ас-Саади), `src/data/quran-transliteration.ts`, `src/data/quiz.ts`, `src/data/islamic-qa.ts`, `src/data/stories.ts`, `src/data/seerah.ts`, `src/data/prophets.ts`, `src/data/terms.ts`, хадисы.

## 2. СНАЧАЛА ПОЧИНИ БАГИ (P0 — до новых фич)

Эти дефекты найдены при тестировании прода. Чинить в первую очередь — они бьют по достоверности текста Корана и по доверию.

**2.1. 🔴 Басмала в аяте №1 (системный баг данных).**
У первого аята КАЖДОЙ суры арабский текст содержит вшитую «بِسْمِ اللَّهِ الرَّحْمَٰنِ الرَّحِيمِ» в начале, тогда как транскрипция и перевод её НЕ содержат, и басмала уже отдельно отрисована как заголовок суры. Итог: дублирование басмалы + арабский не совпадает с переводом/транскрипцией.
- Исправь рендер первого аята: убирай префикс-басмалу из арабского текста аята 1.
- Исключения: сура **1 (Аль-Фатиха)** — там басмала является законным аятом 1, оставить; сура **9 (Ат-Тауба)** — басмалы нет вовсе.
- Гарантируй, что арабский, транскрипция и перевод одного аята строго соответствуют. Проверь на сурах 1, 2, 9, 112. Затрагивает как `Quran.tsx`, так и `Memorize.tsx` (единый источник данных).

**2.2. 🔴 Прогресс чтения врёт (атрибуция).**
Прогресс начисляет аяты и помечает суры прочитанными без действия пользователя (воспроизведено: открыл суру 50 — отметилась прочитанной сура 3 на 200 аятов). Найди и почини логику инкремента — она привязывается к неверному `surahId`/индексу. Проверь `readingTimer.ts`, `storage.ts`, `Quran.tsx`.

**2.3. 🔴 Открытие суры ≠ прочтение.**
Сейчас открытие суры автоматически засчитывает все её аяты как «прочитано», прогресс надувается. Прогресс должен расти только по явному действию (скролл до аята + подтверждение, либо кнопка «отметить прочитанным»).

**2.4. ⚠️ Хифз: новая сура сразу 50%.**
Только что добавленная в заучивание сура показывает 50% прогресса при 0 повторений. Новая сура должна стартовать с 0%. Проверь инициализацию SRS-состояния (уровень/интервал/прогресс) в `Memorize.tsx`.

**2.5. ⚠️ Аудио Корана: счётчик «Аят N из M» не продвигается / медленно.**
Плеер стартует, но переход между аятами залипает. Реализуй предзагрузку следующего аята и корректный переход по `onended`, добавь буферизацию и обработку ошибок сети.

**2.6. ⚠️ «Обои» без обратной связи.**
По клику на «Обои» нет ни превью, ни подтверждения скачивания (тихо). Сделай модалку с превью сгенерированной картинки (аят + транскрипция + перевод) и явной кнопкой «Скачать». Проверь работу на iOS Safari (там download работает иначе — возможно, нужно открытие изображения в новой вкладке / share-sheet). Файл: `src/lib/wallpaper.ts`, `Wallpapers.tsx`.

**2.7. ⚠️ Локация и метод намаза.**
- Показывай город на экране «Намаз» рядом с датой (обратный геокодинг по уже используемым координатам). Если геолокация запрещена — баннер «Определите город вручную» + поиск города.

  (Проверено: времена по MWL для Бишкека совпадают с эталоном до минуты, ханафитский Аср корректно позже — сам расчёт верный, вопрос только в дефолте и в отсутствии названия города.)

## 6. ФИЧА 4 — AI-ассистент в админке + база знаний (ГЛАВНОЕ, ДВИГАТЕЛЬ КОНТЕНТА)

**Суть:** только для админа — ИИ, подключённый к базе знаний проекта (Коран, тафсир Ас-Саади, хадисы, qa, seerah, prophets, terms). Два режима:
1. **Ассистент Q&A** — админ спрашивает, ИИ отвечает строго на основе базы, с цитатами (RAG, не «из головы»).
2. **Генератор контента** — ИИ выдаёт готовые записи в форматах фич 1–3 (`AdabScenario`, `QA`, `Story`) с источниками, для ревью и публикации. Это движок «тысяч уровней».

### 6.1. Сервер (`server.js`)
- Новый эндпоинт `POST /api/admin/ai` по образцу существующих. Тело: `{ mode: "chat" | "generate", prompt, params }`.
- **Безопасность (критично):** проверяй админа НА СЕРВЕРЕ:
  - валидируй Telegram `initData` через HMAC c `BOT_TOKEN` (переиспользуй `createHmac`, как для вебхука);
  - извлекай `telegram_id` из подписанных данных и сверяй со списком админов (вынеси `ADMIN_TELEGRAM_IDS` в общий/серверный модуль). Не доверяй клиентскому `isAdmin`.
- **API-ключ ИИ — только в env** (`GEMINI_API_KEY` или `ANTHROPIC_API_KEY`, Railway Variables). Никогда на клиент, никогда в git.
- Провайдер-агностик: тонкий адаптер `aiProvider` с реализациями Gemini и Anthropic (`@anthropic-ai/sdk` уже стоит). Модель и провайдер выбираются env-переменной. Актуальную модель уточни на момент разработки.
- Rate-limit и логирование запросов админ-ИИ (в `analytics` или отдельную таблицу).

### 6.2. База знаний (RAG)
- Корпус: `tafsir-saadi.json`, перевод+транскрипция Корана, `quiz.ts`, `islamic-qa.ts`, `stories.ts`, `seerah.ts`, `prophets.ts`, `terms.ts`, хадисы.
- Скрипт `scripts/build-kb.ts`: чанкует корпус (аят / абзац тафсира / одна QA = чанк) с метаданными `{ source, ref, category }`.
- Хранилище: **pgvector** в существующем Postgres. Добавь таблицу и миграцию в `schema.sql`:
  ```sql
  CREATE EXTENSION IF NOT EXISTS vector;
  CREATE TABLE IF NOT EXISTS kb_chunks (
    id SERIAL PRIMARY KEY,
    content TEXT NOT NULL,
    embedding vector(768),          -- размерность под выбранную модель эмбеддингов
    metadata JSONB NOT NULL
  );
  CREATE INDEX IF NOT EXISTS idx_kb_embedding ON kb_chunks USING ivfflat (embedding vector_cosine_ops);
  ```
  Для MVP допустим полнотекстовый поиск Postgres (`tsvector`) без эмбеддингов, но эмбеддинги дадут лучшую релевантность — заложи возможность переключения.
- Ретрив: на запрос → top-k чанков → в контекст модели с инструкцией «отвечай только на основе контекста, указывай источники; если данных недостаточно — так и скажи».

### 6.3. Клиент (админка `AdminNew.tsx`)
- Новая вкладка «AI-студия», видна только при `isAdmin`.
- Режим «Чат»: вопрос → ответ с раскрытыми источниками-цитатами.
- Режим «Генератор»: выбор типа (`Сценарий адаба` / `Вопрос QA` / `История`), тема, количество, сложность/категория → ИИ возвращает **валидный JSON строго по интерфейсу** → предпросмотр карточек → «Одобрить» / «Отклонить» / «Редактировать».
- **Гейт публикации:** одобренные записи идут в очередь ревью и экспортируются (в `src/data/*.ts` через PR либо в БД-таблицу контента). Ничего не публикуется в обход ручного одобрения.

### 6.4. Системный промпт генератора (зашей в эндпоинт)
> «Ты — помощник по исламскому контенту ханафитского мазхаба. Генерируй/отвечай строго на основе переданного контекста базы знаний. Каждой единице контента проставляй достоверный `source` (аят сура:аят / хадис сборник+номер / фетва). Если данных в контексте недостаточно — верни `needsReview: true` и пояснение, не выдумывай. Выводи ТОЛЬКО валидный JSON по указанной схеме, без текста вне JSON. Соблюдай уважительные формулы после имён.»

**Баги:**

5. «Обои» показывают превью + явную кнопку скачивания (проверено на iOS Safari).
6. На экране намаза виден город; для СНГ метод по умолчанию — САДУМ; есть ручной выбор города.

**Фичи:**
7. Роуты `/adab`, `/adab/:chapterId`, `/adab/:chapterId/:scenarioId` работают; прогресс в JSONB, синкается.
8. Reels-режим QA листает ≥1000 вопросов без повторов, с фильтром и источниками.
9. Истории фильтруются по `reliability` и категории; у каждой есть `source`.
10. `POST /api/admin/ai` доступен ТОЛЬКО админам (серверная проверка `initData`); ключ ИИ в env.
11. AI-генератор возвращает валидный JSON по интерфейсам `AdabScenario`/`QA`/`Story`; предпросмотр и ручное одобрение работают; без одобрения ничего не публикуется.

**Качество:**
12. `npm run build` и `npm run lint` — без ошибок. Строгий TS, без `any` в новом коде.
13. Никаких секретов в репозитории; `.gitignore` проверен.
