> Он привязан к реальной архитектуре проекта `iman-app`. Не переписывай существующее — **расширяй**.

## КОНТЕКСТ ПРОЕКТА (изучи перед работой)

Ты работаешь над **IMAN** — Telegram Mini App для мусульман (трекер намазов, Коран, хифз, геймификация).

**Стек:**
- Фронт: **React 19 + TypeScript + Vite + Tailwind v4 + react-router-dom v7**, PWA (`vite-plugin-pwa`).
- Бэк: **«голый» Node** `http.createServer` в `server.js` (без Express) + **Postgres** (`pg`).
- Авторизация: **Telegram** (`initData`, `BOT_TOKEN`). Синк прогресса: `POST/GET /api/user/:telegramId` → таблица `users(telegram_id BIGINT PK, data JSONB, updated_at BIGINT)`.
- Аналитика: таблица `analytics`.
- Локальный контент: TypeScript-массивы в `src/data/*.ts`. Тафсир Ас-Саади — `src/data/tafsir-saadi.json` (~11 МБ).

**Роутинг фронта** — в `src/App.tsx` (`<Routes>`), страницы в `src/pages/`, данные в `src/data/`, клиент API и утилиты в `src/lib/` (`api.ts`, `storage.ts`, `sync.ts`, `analytics.ts`, `adminConfig.ts`).

**Роутинг бэка** — ручной матчинг в `server.js`: `if (req.url === "/api/..." && req.method === "GET") {...}`. Существующие эндпоинты: `/api/user/:id` (GET/POST), `/api/admin/users`, `/api/admin/analytics`, `/api/analytics`, `/api/leaderboard`, `/api/dua-wall`, `/health`.

**Админ-доступ** — `src/lib/adminConfig.ts`: `isAdmin(telegramId, username)` по списку `ADMIN_TELEGRAM_IDS`. ⚠️ Проверка сейчас **только на клиенте** — для новых админ-эндпоинтов добавь проверку на сервере (см. фичу 4).

**Уже готовые движки (переиспользуй их UX и паттерны):**
- Игра-уровни: `src/pages/Quest.tsx`, `QuestWorldMap.tsx`, `QuestLevel.tsx` + `src/data/quest.ts`.
  Модель: `QuestWorld { id, emoji, title, subtitle, color, levels[] }`, `QuestLevel { id, title, questions[], rewardSawab, isBoss? }`, `QuestQuestion { q, options:[4], correctIdx, explanation, source? }`.
- Вопросы-карточки: `src/pages/IslamicQA.tsx` + `src/data/islamic-qa.ts`.
  Модель: `QA { id, category, q, a, source? }`, `QA_CATEGORIES` (10 категорий).
- Квиз: `src/pages/Quiz.tsx` + `src/data/quiz.ts` (`QuizQuestion { id, category, question, options:[4], correctIndex, difficulty, explanation }`).
- Истории: `src/pages/Stories.tsx` + `src/data/stories.ts`.
  Модель: `Story { id, title, subtitle, category, icon, readTime, xp, content, source?, reliability? }`, где `reliability: "sahih" | "hasan" | "siyar" | "daif"` (уже есть визуальные бейджи в `RELIABILITY_INFO`).

**Общие правила достоверности (соблюдай во всём контенте):**
- Мазхаб по умолчанию — **ханафитский** (аудитория — Кыргызстан/СНГ). Где мнения расходятся — указывай это.
- Каждое религиозное утверждение снабжай источником (аят, хадис с номером сборника, фетва).
- Никакого ИИ-муфтия для пользователей: ИИ генерит контент только в админке, **всё проходит ручную проверку человеком перед публикацией**.
- Тон — уважительный, после имён пророков «ﷺ» / «عليه السلام», после сподвижников «رضي الله عنه».

## ФИЧА 1 — Игра «Как поступает мусульманин» (поведенческие сценарии)

**Суть:** пользователь оказывается в жизненной ситуации и выбирает, как поступить. После выбора — разбор: правильно/неправильно по Сунне, что произойдёт, и как поступил в похожей ситуации Пророк ﷺ или сподвижник. Тысячи сценариев, разбитые на уровни/этапы.

**Не путать с Quest** (там викторина на знание). Здесь — **адаб/поведение**: моральный выбор + далиль + пример из Сунны.

**Новая модель данных** — создай `src/data/adab.ts`:

```ts
export type AdabCategory =
  | "daily" | "family" | "money" | "work"
  | "worship" | "social" | "trials" | "speech";

export interface AdabChoice {
  text: string;              // вариант поведения (от 1-го лица)
  correct: boolean;          // соответствует ли Сунне/шариату
  outcome: string;           // что произойдёт по этому выбору (последствие)
  explanation: string;       // почему так/не так — с далилем
  companionExample?: string; // как поступил Пророк ﷺ / сподвижник в похожем
  source?: string;           // аят / хадис (сборник + номер) / асар
}

export interface AdabScenario {
  id: number;
  category: AdabCategory;
  title: string;
  situation: string;         // описание ситуации (от 2-го лица: «Ты…»)
  choices: AdabChoice[];     // 2–4 варианта, минимум 1 correct
  sawab: number;             // награда за верный выбор
  difficulty: "easy" | "medium" | "hard";
  tags?: string[];
}

// Группировка в «главы»/этапы по образцу QuestWorld
export interface AdabChapter {
  id: string;
  emoji: string;
  title: string;
  subtitle: string;
  color: "emerald" | "amber" | "rose" | "violet" | "sky" | "teal" | "indigo";
  scenarios: AdabScenario[];
}

export const ADAB_CHAPTERS: AdabChapter[] = [ /* заполняется конвейером фичи 4 */ ];
```

**Экраны и роуты** (добавь в `src/App.tsx`), переиспользуй визуал `Quest*`:
- `/adab` — карта глав (по образцу `QuestWorldMap`), прогресс по каждой главе.
- `/adab/:chapterId` — список сценариев-уровней.
- `/adab/:chapterId/:scenarioId` — экран сценария: `situation` → варианты → после выбора анимированный разбор (`outcome` + `explanation` + `companionExample` + `source`), начисление `sawab`, кнопка «Дальше».

**Интеграция геймификации:** используй существующую систему саваба и прогресса (см. как это делает `QuestLevel.tsx` и `storage.ts`). Прогресс сценариев храни в том же `data` JSONB пользователя (ключ `adabProgress`).

**Масштаб:** старт — 8 глав × ~15 сценариев (ручной эталон качества). Дальше до 1000+ сценариев — генерацией через фичу 4. Каждый сценарий обязан иметь минимум один вариант с далилем и пример из Сунны.

## ФИЧА 2 — «1000 вопросов об исламе» (лента-перелистывание)

**Суть:** поток из ~1000 коротких, интересных, разнообразных вопросов с ответами уровня алима, в формате быстрой ленты (свайп/переключение). Примеры вопросов пользователя:
- «Почему Коран был ниспослан именно в то время и именно так — по частям, 23 года?»
- «Почему у пророков были явные знамения (муджизаты), а у людей сейчас их нет?»
- «Почему намаз именно 5 раз, а не 3 или 7?»

**Переиспользуй существующую модель `QA`** (`src/data/islamic-qa.ts`) — она уже правильная (`{ id, category, q, a, source? }`). Не плоди новую.

**Что сделать:**
1. Расширь `QA_LIST` до ~1000 записей (через конвейер фичи 4). Добавь при необходимости категории (напр. `"hikma"` — мудрость/смыслы, `"history"`, `"science"`).
2. Новый режим показа — добавь в `IslamicQA.tsx` (или отдельная страница `/qa/reels`): **вертикальная лента-карточка** в стиле reels:
   - одна карточка = один вопрос; тап/свайп → следующий (рандом без повторов до конца пула);
   - на карточке: вопрос крупно → раскрытие ответа по тапу → источник внизу мелким;
   - фильтр по категории, кнопки «сохранить в избранное» (переиспользуй `Favorites`), «поделиться» (`ShareCard.tsx`).
3. Начисляй небольшой саваб за прочитанные карточки (антифрод: не более N в день), чтобы связать с геймификацией.

## ФИЧА 3 — Достоверные истории людей

**Суть:** интересные, достоверные истории (сподвижники, покаяния, чудеса, уроки, современные примеры), с «открытым интернетом» как источником — но **только через админ-проверку**.

**Переиспользуй `src/data/stories.ts`** — модель `Story` уже содержит `reliability` (sahih/hasan/siyar/daif) и `source`. Это и есть механизм достоверности.

**Важно про «открытый интернет»:** пользователям НЕ отдаём непроверенный веб-контент напрямую (риск недостоверных религиозных сведений). Вместо этого:
- В админке (фича 4) ИИ **ищет и черновиково собирает** истории из открытых источников, **обязательно** проставляя `source` и предполагаемый `reliability`.
- Ты (админ) проверяешь → одобряешь → история попадает в `STORIES` как статические данные.
- Флаг `reliability: "daif"` показывать честно («известный рассказ, цепочка не подтверждена»).

**Что сделать:** расширить `STORIES` до крупного пула через конвейер; добавить в `Stories.tsx` фильтр по `reliability` и по категории; связать XP с геймификацией (уже есть поле `xp`).

## ФИЧА 4 — AI-ассистент в админке + база знаний (ГЛАВНОЕ)

**Суть:** только для админа — ИИ, подключённый к базе знаний проекта (Коран, тафсир Ас-Саади, хадисы, qa, seerah, prophets, terms). Работает в двух режимах:
1. **Ассистент Q&A** — админ спрашивает, ИИ отвечает с цитатами из базы (RAG, а не «из головы»).
2. **Генератор контента** — ИИ выдаёт готовые записи в TS-форматах фич 1–3 (`AdabScenario`, `QA`, `Story`), с источниками, для ревью и публикации. Это движок «тысяч уровней».

### Архитектура (сделай так)

**Сервер (`server.js`):**
- Новый эндпоинт `POST /api/admin/ai` (по образцу существующих). Тело: `{ mode: "chat" | "generate", prompt, params }`.
- **Безопасность (критично):** проверяй админа **на сервере**:
  - валидируй Telegram `initData` HMAC (`BOT_TOKEN`) — переиспользуй крипто-логику, что уже есть в `server.js` для вебхука (`createHmac`);
  - извлекай `telegram_id` из подписанных данных и сверяй со списком админов (перенеси `ADMIN_TELEGRAM_IDS` в общий модуль или продублируй серверно). Никакого доверия к клиентскому `isAdmin`.
- **API-ключ ИИ — только в env** (`GEMINI_API_KEY` или `ANTHROPIC_API_KEY`), Railway Variables. Никогда не на клиент, никогда в git.
- Провайдер-агностик: тонкий адаптер `aiProvider` с реализациями Gemini и Anthropic (в проекте уже стоит `@anthropic-ai/sdk`). Модель выбирается env-переменной. По умолчанию можно Gemini (`gemini-1.5-pro` или новее — уточни актуальную модель на момент разработки).

**База знаний (RAG):**
- Источник корпуса: `src/data/tafsir-saadi.json`, перевод/транскрипция Корана (`api.ts` / `quran-transliteration.ts`), `quiz.ts`, `islamic-qa.ts`, `stories.ts`, `seerah.ts`, `prophets.ts`, `terms.ts`, хадисы (`Hadiths.tsx`/api).
- Пайплайн: скрипт `scripts/build-kb.ts` — чанкует корпус (аят/абзац тафсира/одна QA = чанк с метаданными `{source, ref, category}`).
- Хранилище векторов: **pgvector** в существующем Postgres (добавь таблицу `kb_chunks(id, content, embedding vector, metadata jsonb)` и миграцию в `schema.sql`). Для MVP допустим BM25/полнотекст Postgres без эмбеддингов, но эмбеддинги дадут лучшую релевантность.
- Ретрив: на запрос — top-k чанков → в контекст модели с инструкцией «отвечай только на основе контекста, указывай источники, при недостатке данных — так и скажи».

**Клиент (админка `AdminNew.tsx`):**
- Новая вкладка «AI-студия» (видна только если `isAdmin`).
- Режим «Чат»: поле вопроса → ответ с раскрытыми источниками-цитатами.
- Режим «Генератор»: выбор типа (`Сценарий адаба` / `Вопрос QA` / `История`), тема, количество, сложность/категория → ИИ возвращает **валидный JSON строго по интерфейсу** → предпросмотр карточек → кнопки «Одобрить» / «Отклонить» / «Редактировать».
- **Гейт публикации:** одобренные записи складываются в очередь на ревью и экспортируются (в `src/data/*.ts` через PR, либо в БД-таблицу контента). Ничего не публикуется в обход ручного одобрения.

**Промпт-инжиниринг для генератора (зашей в системный промпт эндпоинта):**
- «Ты — помощник по исламскому контенту ханафитского мазхаба. Отвечай/генерируй строго на основе переданного контекста базы знаний. Каждой единице контента проставляй достоверный `source`. Если данных недостаточно — верни поле `needsReview: true` и пояснение. Выводи только валидный JSON по указанной схеме, без пояснений вне JSON.»

## КРИТЕРИИ ПРИЁМКИ

1. Новые роуты `/adab`, `/adab/:chapterId`, `/adab/:chapterId/:scenarioId` работают, прогресс сохраняется в JSONB пользователя и синкается через `/api/user/:id`.
2. Режим reels в QA листает ≥1000 вопросов без повторов, с фильтром и источниками.
3. Истории фильтруются по `reliability` и категории; у каждой есть `source`.
4. `POST /api/admin/ai` доступен **только** админам (серверная проверка `initData`), ключ ИИ — в env, не на клиенте.
5. AI-генератор возвращает валидный JSON по интерфейсам `AdabScenario` / `QA` / `Story`; предпросмотр и ручное одобрение работают; без одобрения ничего не публикуется.
6. `npm run build` и `npm run lint` проходят без ошибок. TypeScript строгий, без `any` в новом коде.
7. Никаких секретов в репозитории; проверь `.gitignore` перед коммитом.

## ПОРЯДОК РАБОТЫ (поэтапно, не всё сразу)

1. Модель `adab.ts` + экраны `/adab` на переиспользовании `Quest*` (8 глав эталонного качества вручную).
